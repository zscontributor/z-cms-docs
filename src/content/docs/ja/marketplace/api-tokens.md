**API トークン**は、ブラウザーのログインセッションを使わずに、プログラムから Marketplace へパッケージを提出するための認証情報です。主に次の二つの場面で使用します。

- **Z-CMS のテーマエディター：** 管理画面で作成したテーマを署名・提出するときに、**マーケットプレイスアカウントを接続**から登録します。
- **スクリプトや CI：** 提出 API を直接呼び出す際に使用します。

トークンの権限範囲は `submissions:write` のみで、パッケージの提出と、下記 API による提出状況の確認に使います。パッケージへの署名、別のトークンの作成、公開者の鍵の登録・更新、範囲外の非公開データの取得はできません。署名には引き続き公開者の秘密鍵を使い、鍵は署名を行う端末やブラウザーの外へ送信しません。トークンは署名済みパッケージのアップロードを認証するものです。

## トークンを作成する

**Developer Portal → Tokens** を開いて作成します。

1. **ラベル（Label）：** 自分だけに表示される識別名です。`my laptop` や `acme CI` など、用途が分かる名前を付けます。
2. **有効期限（Expiry）：** なし、30 日、90 日、365 日から選びます。長期間使う場合も期限を設定し、定期的に更新してください。期限を過ぎると Portal はトークンを拒否します。

**作成**を選ぶと、`zcms_pat_…` 形式のトークン全体が一度だけ表示されます。その場でコピーし、安全な場所に保存してください。Portal にはハッシュ値だけが保存されるため、後からトークン全体を表示することはできません。紛失した場合は失効させ、新しく作成します。

## トークンを使う

### Z-CMS 管理画面から

テーマエディターの**公開**パネルで「**マーケットプレイスアカウントを接続**」を開き、トークンを貼り付けて**接続**を押します。トークンは暗号化して保存され、以後表示されません。以降、「**署名して提出**」がこのトークンで署名済みパッケージをアップロードします。

### スクリプトや CI から

提出 API を呼び出す際、Bearer 認証でトークンを送信します。

```bash
curl -X POST https://marketplace.z-cms.org/api/v1/developer/submissions \
  -H "Authorization: Bearer zcms_pat_…" \
  -F "file=@corporate-1.2.0.zcms"
```

提出の一覧・追跡も同じトークンで行えます。

```bash
curl https://marketplace.z-cms.org/api/v1/developer/submissions \
  -H "Authorization: Bearer zcms_pat_…"
```

パッケージの上限は 20 MB です。各開発者アカウントは、直近 1 時間で最大 10 件まで提出できます。パッケージ ID、バージョン、公開者は、署名付きのパッケージ情報から読み取られます。トークンが証明するのは、アップロードしているアカウントです。

## 管理と失効

一覧には、ラベル、識別用の先頭部分（`zcms_pat_` と数文字）、作成日時、最終使用日時、有効期限が表示されます。表示される先頭部分だけでは認証できません。

**失効（Revoke）**を選ぶと、トークンはすぐに無効になります。それ以降のリクエストは拒否されます。漏えいが疑われる場合、端末の利用を終了する場合、CI の認証情報を更新する場合は、不要になったトークンを失効させてください。

## トークンを安全に保つ

- **用途ごとに別のトークンを使います。** 個人の端末と各 CI を分ければ、一つを失効させても他には影響しません。
- **有効期限を設定します。** 長期間使う場合も、無期限のまま放置せず定期的に更新してください。
- **Git や公開ページに記載しないでください。** `zcms_pat_` は漏えい検出ツールが識別するための接頭辞ですが、漏えいに気付いたら検出を待たずに失効させます。
- **手元のトークン全体を保護してください。** Portal はハッシュ値だけを保存しますが、端末、CI、秘密情報ストアにある元の値はパスワードと同様に扱う必要があります。
