Z-CMS では、各サイトのメンバーにロール（役割）を割り当ててアクセス権限を管理します。同じユーザーでも、サイトごとに異なるロールを持つことができます。

## 標準ロール

| ロール | 主な操作 |
| --- | --- |
| Viewer（閲覧者） | サイト情報、コンテンツ、メディア、テーマ、プラグイン、設定の閲覧 |
| Author（投稿者） | コンテンツの作成、権限のあるコンテンツの編集、メディアのアップロードと更新 |
| Editor（編集者） | コンテンツの公開・削除、メディアの削除、メニューの管理 |
| Admin（管理者） | サイト、コンテンツタイプ、テーマ、プラグイン、メールの設定とユーザーの招待 |
| Owner（所有者） | サイトの作成・削除、ユーザーの管理、隔離されたパッケージの確認 |

ロールは、あらかじめ定義された権限のセットです。ロールに加えて、リソースごとの権限も確認されます。Author はコンテンツを公開できず、Admin が自分自身を Owner に昇格させることもできません。

## メンバーを招待する

1. **Users** を開き、アクセスを付与するサイトを選択します。
2. メールアドレスを入力し、自分が持つ最上位のロールを超えない範囲でロールを選びます。
3. 招待を送信し、**Pending invitations** で状態を確認します。
4. 受信者はリンクからログインまたは登録し、サイトへの参加を承認します。

Admin はメンバーの閲覧と招待ができます。他のメンバーのロール変更やアクセス削除は Owner のみ可能です。

## プロフィールとパスワード

ログイン中のユーザーは、**Profile** で自分の名前、アバター、パスワードを変更できます。メールアドレスはログイン ID として使われるため、システム設定によっては変更できません。

## 二要素認証

**Profile**（プロフィール）で TOTP（時間ベースのワンタイムパスワード）を有効にします。認証アプリで QR コードを読み取り、表示されたコードを入力して設定を完了します。リカバリーコードは、認証コードを生成する端末とは別の安全な場所に保存してください。

:::danger
各リカバリーコードは 1 回だけ使用できます。公開メモやサポートチケットに記載したり、共有アカウントの情報と同じ場所に保存したりしないでください。
:::

不正アクセスが疑われる場合は、パスワードを変更し、対応していればログインセッションを無効にしてください。サイトごとの権限を見直し、Admin または Owner に監査ログの確認を依頼します。
