Z-CMS では、メール送信、サイズ違いの画像の生成、サイトマップの更新、一部のプラグインフックをワーカーが処理します。これらをバックグラウンドで実行することで、Web リクエストの応答を待たせずに済みます。

## サイトごとのメール設定

**Settings → Mail** を開きます。主な項目は、SMTP ホスト、ポート、暗号化方式、ユーザー名、パスワード、送信者名、送信元アドレスです。設定はサイトごとに保存されるため、編集する前に対象のサイトを選択してください。

1. メールプロバイダーから提供された情報を入力します。
2. 設定を保存します。
3. 受信を確認できるメールアドレスを指定し、**Send test email**（テストメールを送信）を実行します。
4. 受信トレイ、迷惑メールフォルダー、メールプロバイダーのログを確認します。

`settings:read` 権限は設定の閲覧、`settings:update` は変更、`mail:send` はメール送信を許可します。このページには `mail:send` を付与されたプラグインも表示されるため、サイト名義でメールを送信できるプラグインを確認できます。

:::caution
SMTP パスワードをチケットやスクリーンショットに貼り付けないでください。認証情報を更新したら、すぐに再テストします。
:::

## 失敗したジョブ

**Jobs** では、再試行回数の上限に達しても完了しなかったジョブの一覧（デッドレターキュー）を確認できます。メール送信、画像の変換、サイトマップの更新、プラグインフックなどが対象です。

次の手順で対処してください。

1. ジョブ名、時刻、試行回数、エラーメッセージを読みます。
2. SMTP 設定、ストレージ権限、プラグイン障害などの根本原因を修正します。
3. 原因を解消した後にのみ再実行します。
4. ジョブが一覧から消え、メールの送信や画像の生成など、期待した処理が完了したことを確認します。

1 ページに表示できるのは最大 50 件です。一覧が省略されているという警告が表示された場合は、複数回に分けて処理してください。原因を修正せずに再実行を繰り返すと、負荷が増えたり、同じメールが複数回送信されたりする可能性があります。
