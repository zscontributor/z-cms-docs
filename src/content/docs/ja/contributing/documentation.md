ドキュメントは Markdown または MDX で管理し、プルリクエスト（PR）でレビューします。

## 執筆の原則

- 読者が何を達成したいかを最初に示し、一つのページでは一つの作業または主要な概念を扱います。
- メニュー名やボタン名は実際の画面と照合できる表記にし、必要に応じて日本語の説明を添えます。
- コマンド名、API 名、設定フィールド、環境変数、パスは変更しません。コード内の識別子は翻訳しないでください。
- 説明文では「権限」「フィールド」「設定」「公開者」などの表記を統一し、英単語を不必要に混在させません。
- 初めて出てくる専門用語は、対象読者に応じて簡潔に説明します。
- 英語の語順をそのまま写さず、誰が何を行い、どうなるかを短い文で明確にします。
- 記載したバージョンで例が動くことを確認し、実際の秘密情報、認証情報、顧客データを含めません。
- 見出しを変更したら、その見出しを参照する `#` 付きリンクも確認します。
- 製品の動作を変更する場合は、同じ PR でドキュメントも更新します。

## ページ先頭の設定（フロントマター）

```yaml
---
title: 明確なタイトル
description: 読者が達成できることを説明する一文。
---
```

言語を切り替えたときに対応するページへ移動できるよう、各言語で同じ相対パスを使います。編集後は `pnpm build` を実行し、翻訳の内容とリンクを確認してください。
